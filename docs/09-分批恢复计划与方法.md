# 分批恢复计划（UFS Explorer 选择性导出）

> 源盘：4TB NVMe-4TB（pRDM 直通），btrfs 数据分区约 3.7TB，实际数据约 1.4TB
> 读取机：jump-host-a（RDM 挂为 Hard disk 2，3726 GB）
> 目标盘：**R: 1100GB**（SSD-1TB） + **S: 500GB**（datastore-b）
> 家族：C3RB3R，后缀 `.L0CK3D`，无公开解密器，只能靠 btrfs 未分配空间残留

---

## 一、核心机制：扫描一次，导出多次

1. 物理盘 → 数据分区（约 3.6TB）→ **Scan for lost data** → 只勾 Btrfs → 扫描
2. 扫描结果 → **Save this item** 存 `.vfs` 到 `R:`（防崩溃重扫；注意加载时源盘仍需连接）
3. 之后每一批：打开 `.vfs` → 挑目录 → **Define selection** → **Save selection** → 选目标盘

**扫描只需做一次，导出想做多少次都行，不用重扫。**

---

## 二、怎么区分「原始文件」和「加密后的文件」

结果树里两类文件会混在一起，按这个优先级判断：

| 判据 | 原始文件（要的） | 加密文件（不要的） |
|---|---|---|
| **后缀** | 正常后缀，`**没有** .L0CK3D` | `*.L0CK3D` |
| 修改日期 | 早于 **2026-10-28** | 2026-10-28 及之后 |
| 大小 | 与记忆相符 | 略大（尾部多了 RSA 封装密钥块） |
| 位置标记 | 常带红色删除标记，或归入 Deleted / Lost & Found 虚拟目录 | 正常目录里可见 |

**第一判据永远是后缀。** 先把所有 `.L0CK3D` 排除掉，剩下的才是候选。

---

## 三、批量选中的两种方法

- **按目录**：在结果树里右键某个目录 → `Define selection` → `Save selection`
- **按条件**：工具栏搜索框 → 设置过滤器（扩展名 / 大小区间 / 修改日期）→ 对结果集全选 → `Define selection`

推荐组合：先按「修改日期 < 2026-10-28」过滤，再按目录挑，能一次性排除掉全部 `.L0CK3D`。

---

## 四、分批原则：先小后大、先高价值后低价值

残留率有不确定性，所以**不要一上来就拉最大的目录**——万一那批全坏，白耗几小时和目标盘空间。

| 批次 | 内容 | 建议体积 | 说明 |
|---|---|---|---|
| **批 1** | 文档 / 表格 / 数据库 / 代码 / 配置文件 | < 50 GB | 先做，用来**验证残留率**。这批成了，后面就有底 |
| **批 2** | 照片 / 设计源文件（JPG RAW PSD AI CDR） | — | 单文件小、总量可控，性价比高 |
| **批 3** | 影音大文件（MP4 MOV MKV AVI） | — | 体积大，先确认前面批次成功率再决定 |
| **批 4** | 可再生内容（安装包、系统镜像、下载目录、缓存） | — | 优先级最低，能不要就不要 |

---

## 五、每批必做：抽样验证

导出前从该批里**随机抽 3~5 个文件**，用 UFS Explorer 内置预览打开：

- 能正常打开 → 整批导出
- 打不开 / 内容为乱码 → 这批残留已被覆写，**整批降级**，跳到下一批，别浪费时间

这一步能避免"导了 500GB 全是坏文件"。

## 八、红线（全程遵守）

- 保存路径**绝不能**指向源盘（3726 GB 那个）
- 不点任何「格式化 / 修复 / chkdsk」
- 不用 ext2fsd / Paragon 等**可写**驱动挂载源盘
- Windows 提示「需要格式化」→ 一律点**取消**
- 全部批次确认完毕前，**不要关机移除 RDM**
